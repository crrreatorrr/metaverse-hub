# PR08 durable job continuation contract (draft)

An internal job owns an immutable logical input range `[tick0,tick_end)` inside exactly one accepted public batch. `input_sha256` is the digest of that original whole batch, including its original sequence and tick0; slicing never creates a new public acknowledgment or recomputes a digest for invented batch bytes. `initial_revision` never changes. The mutable `expected_revision` and `continuation_tick` identify the next authoritative predecessor, while the original range remains immutable. A continuation can begin inside the same batch.

Claim atomically verifies `continuation_tick = run.verified_tick`, `expected_revision = run.revision`, binding and manifest, and increments a monotonic fence and attempt count. It records a bounded immutable attempt claim before returning private work. No SQL transaction spans simulation. An attempt's lease can renew only within a finite absolute attempt deadline; renewal cannot retain a concurrency slot indefinitely. After expiry, both success and failure from that fence are stale. Reclaim uses a new fence. Operational retry state persists exponential bounded backoff; exhaustion quarantines with pending-support status, never invalid_gameplay.

PR11 may commit a fenced retryable partial result only when its complete private checkpoint and cumulative counters match the authoritative predecessor and immutable accepted range. In one transaction it advances run revision/checkpoint/cursors, writes immutable attempt-result evidence, moves the same job's continuation cursor and predecessor revision, then releases the attempt to retry_wait. It does not rewrite original range/digest or create one job per 1-tick timeout. Once the planned input range is resolved, the job completes with immutable verified acknowledgment. First terminal evidence freezes simulation tick; structurally validated previously accepted trailing input still advances verified input cursor independently. A terminal inside a planned range must not silently discard its suffix.

PR08 exposes only unused module functions/SQL helpers. PR10 introduces scoped service authentication and transport. Public users cannot invoke generic claims or completion, and job APIs never select payouts. Bound claims are not authority to settle after original session expiry; accepted work can still verify for an explanation.

Scheduler is default-off and requires explicit finite concurrency, per-account concurrency, retained jobs/attempt receipts/checkpoint bytes, lease duration, absolute attempt lifetime, attempts and retry delays. Absent capacity yields operational pending without discarding input. Cap checks and quota counters are transactional with insertions. No evidence deletion or active checkpoint garbage collection is introduced. New issuance must inspect these limits in its future gate; no safe capacity is inferred from CI.

Fair scheduling orders eligible accounts by last successful claim, then picks their oldest predecessor-ready run. Claim/reclaim/renew/retry use a consistent short scheduler/config -> account -> run -> job lock order and current clock sampled after lock acquisition. All worker decisions, including stale failures, validate the same fence/owner/revision/cursor predicate. A global active-lease bound includes unexpired old workers; expiry makes their outputs unable to commit. Operationally stale processes must also be terminated by the isolated service's process budget.

Required real Postgres tests: concurrent claims, predecessor mismatch, concurrent noisy-account fairness, global/account saturation, expiry while old worker runs, old success and failure refusal, finite renewal deadline, attempts/backoff/quarantine, restart-stable counters and queue state, and atomic quota admission races. No timeout raises or local implementation execution.

## PR08 implementation boundary

Migration 0052 adds disabled scheduler configuration, account scheduling cursors, immutable logical-job bindings, continuation cursors and append-only attempt/result evidence. `ShooterVerificationJobs` wraps SQL decisions but registers no RPC. No successful advancement or payment function exists in PR08: `fence_live` is the shared predicate required by the future PR11 transaction, not an independent grant to advance state. Real completion with partial progress remains a PR11 dependency.

Each claim makes at most 256 account considerations. The per-account considered timestamp advances even when capacity blocks an account, preventing permanently saturated users from hiding other eligible users behind a bounded scan. Account selection is round-robin by least recently considered, with the oldest eligible run inside each account; only successful claims update last_claim_at. The first attempt resolves at most 4096 planned input ticks, with smaller configured slices permitted. A retryable early source return continues the same immutable job; it does not reserve a fresh row for each partial tick.

Finite retained job and logical attempt counts imply finite fixed-width row payloads: job IDs/bindings/hashes/ranges have bounded SQL types; attempts store claim metadata and one fixed-width result, without arbitrary worker JSON, full input or duplicate private checkpoints. Each retained logical attempt reserves at most one result row. Full checkpoint storage reserves one 16 MiB slot per claimed run globally and per account, before the first claim; the reservation persists through quarantine and restart. Actual PostgreSQL index, TOAST, WAL, backups and process overhead are unmeasured and outside this payload allowance. The authoritative checkpoint writer and exact byte accounting are future PR11 work. No old snapshot or evidence is deleted here.

When a configured retained-job, attempt, checkpoint-slot or live-lease cap is full, work remains durable and pending. Renewals remain possible after disabling new claims, bounded by the original immutable attempt deadline. Existing work can drain independently of PR07's stop-new-runs control. New issuance remains absent and cannot be enabled through this PR. PR10 must rederive worker claim/owner authorization and PR11 must bind manifest, original batch, counters, fence, revision and continuation before using a result. A valid worker echo alone is not authority.
