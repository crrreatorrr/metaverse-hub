# The People's Bitcoin: online worlds (`pb_world`)

The People's Bitcoin (PB) runs its whole game server-side here: numbered worlds of up to 100 players, RuneScape-style mechanics (600 ms ticks, click-to-move intents, public and private chat, friends and ignore lists, two-screen trades), with the game's own simulation. Design and decisions: the PB repo's `DECISIONS.md` § "Multiplayer worlds (0.7.0)".

## Pieces

| File | Role |
| --- | --- |
| `server/modules/vendor/pb-sim.js` | Generated by PB's `npm run build:sim` (do not edit). Defines `PB_SIM_VERSION` and `PbSim.createWorldHost`, the pure world host: sim, content, AOI, chat, trade, Ticket batching. Its module body runs lazily on the first call (each match VM evaluates the whole `index.js`). |
| `server/modules/src/games/pb_world.ts` | The match shell: maps match callbacks onto the host and gives it its I/O (storage, `HubEconomy`, match signals, the logger). |
| `server/modules/src/games/pb_rpcs.ts` | `pb.worlds`: the world list for world select. `pb.bench` (dev only, answers when the runtime env has `PB_DEV_RPCS=1`): runs PB's world bench inside this runtime and returns phase timings. |
| `server/modules/src/games/pb_sim.d.ts`, `pb_nakama.d.ts` | Typings for the bundle, and `Context.matchId` by interface merging. |
| `server/test/games/pb_world.test.ts` | Offline test through the hub harness. |

## Flow

1. The client redeems its portal ticket (`init('peoples-bitcoin')`), opens `realtimeFromSdk(sdk)` and calls `pb.worlds`.
2. `pb.worlds` reads `pb_registry/world-<n>` (system user) for n = 1..max(`PB_WORLDS`, default 2; highest registered). A row whose match is gone (`matchGet` null) is replaced by `matchCreate("pb_world", { world: n })`, written with the read version (OCC). On a race the winner's id is used, and the loser's empty match closes itself after about a minute. When every live world has 90+ players, world n+1 opens. Answer: `{ worlds: [{ world, matchId, players, max, sim }], sim }`.
3. The client joins a match id. `matchJoinAttempt` accepts only `ctx.vars` `{ scope: "game", game: "peoples-bitcoin", sid }`, refuses `world_full`, and enforces one world per account: if `pb_online/status` shows the user in another live world, that world is signalled to log them out and the join is refused with `already_online` (the client retries).
4. `matchJoin` loads `pb_character/main`, writes `pb_online/status` and sends `WELCOME`. After the client's `HELLO` (protocol and `PB_SIM_VERSION` must match, else `KICK sim_mismatch`) it gets a `SNAPSHOT`, then a `DELTA` every 600 ms tick.
5. `matchLoop` runs at 5 Hz. Messages are handled every loop; the sim steps every third loop.
6. `matchLeave` starts a logout grace of about 10 s (a reconnect resumes the same character). Then the character is saved and removed.

Label: `{"game":"peoples-bitcoin","kind":"pb_world","world":N,"players":n,"max":100,"open":bool,"sim":"<PB_SIM_VERSION>"}`.

## Opcodes (PB `src/net/protocol.ts`)

| Op | Dir | Body |
| --- | --- | --- |
| 1 HELLO | C→S | `{ proto, sim, client? }` |
| 2 INTENTS | C→S | `{ seq, intents }`, each intent Zod-checked (strict) |
| 3 CHAT | C→S | `{ ch: 'public', text }`, `{ ch: 'pm', to, text }`, `{ ch: 'reply', text }`, `{ ch: 'quick', phrase, pm? }` |
| 4 TRADE | C→S | `{ op: 'request', to }`, `offer`, `remove`, `accept`, `decline` |
| 5 SOCIAL | C→S | add/remove friend or ignore by name; `filters` |
| 7 PING | C→S | `{ t }` |
| 101 WELCOME, 102 SNAPSHOT, 103 DELTA | S→C | session, full view, per-tick changes (entities in view, self patch, events) |
| 104 CHAT, 105 TRADE, 106 SOCIAL | S→C | chat lines, trade screens, friends/ignores/filters |
| 107 KICK | S→C | `sim_mismatch`, `flood`, `superseded`, `world_full`, `shutdown`, `session_expired`, `already_online` |
| 108 PONG | S→C | `{ t, serverTick }` |

Match signals (`nk.matchSignal`): `{ t: 'pm', from, fromName, fromWorld, to, text, quick }` delivers a cross-world PM after the recipient's ignore list and private filter (reply `ok` or `offline`); `{ t: 'kick', uid }` logs a player out (one world per account).

## Persistence

| Collection / key | Owner | Holds | Written |
| --- | --- | --- | --- |
| `pb_character` / `main` | the user (read 0, write 0) | `{ save }`: PB save v7 for one character, plus online social lists | every 100 ticks (one write for every player), on logout, after each trade (both players in one write), on shutdown; always with the read version (`*` for a new one) |
| `pb_online` / `status` | the user (0/0) | `{ world, matchId, at, pf, fr? }` | on join and every 50 ticks; deleted on logout. Older than 3 refreshes = offline |
| `pb_world` / `world-<n>` | system | world economy (Hopium, boss wins) | every 500 ticks and on shutdown |
| `pb_registry` / `world-<n>` | system | `{ matchId, world }` | by `pb.worlds` (OCC) |

A version conflict on a character write means another session wrote it: this world never overwrites it and kicks the player with `superseded`.

## Tickets

Through `HubEconomy` only, with the player's `sid` from `matchJoinAttempt` and the game `peoples-bitcoin`:

- Streams (`pb_drop`, `pb_lobby`, `pb_sell`, the existing PB `event_rule` rows) are batched every 50 ticks and on logout. A batch is sealed into the character save (key `pbw:<sid>:<reason>:<tick>` and amount) before `earn`, so a retry after a crash reuses both; `game.idempotency` makes it exactly-once. `*_cap` keeps the seal for later; `idempotency_mismatch` and `amount_over_rule` drop it and re-read the balance; `session_closed` keeps it and sends `KICK session_expired`.
- Quest rewards use `pb_quest` with PB's existing UUIDv5 keys, so a reward is never paid twice.
- Shop buys and sells call `HubEconomy.spend` / `sell` synchronously in the tick (key `pbw:<sid>:buy|sell:<tick>:<n>`).
- Trades move items only, never Tickets.

## Limits

100 players per world (soft 90 for overflow), 10 intents per tick, 8 messages per loop, 4 KB per message, 5 strikes to a kick, chat rate limits and mutes. All numbers are in PB's `src/config/balance.ts` (`NET`, `CHAT_NET`, `SOCIAL`, `TRADE`, `LOOT`), compiled into the bundle.

## Refreshing the bundle

From the PB repo: `npm run build:sim -- --out ../metaverse-hub/server/modules/vendor/pb-sim.js`, then rebuild the module (`npm run build`). The PB client and the bundle must come from the same PB commit: their `PB_SIM_VERSION` is a hash of PB's sim sources, and a mismatch is kicked with `sim_mismatch`.

## Performance (measured 2026-11-04, Nakama 3.41.0 in Docker, one dev machine)

- `pb.bench` with 100 players in one spot: about 160 ms per sim tick idle, about 275 ms with 10 clicking each tick.
- PB's `scripts/pb-bots.mjs` with 100 real guest bots through the portal, 30 % clicking every tick: all stayed connected, about 17 KB/s per client, and the world logged `loop avg 146 ms` (about 440 ms of the 600 ms tick; the sim runs every third loop).
- The world logs `[pb_world N] P players, loop avg X ms, worst Y ms` about once a minute while anyone is on. If the average climbs past about 180 ms (the tick no longer fits), lower `PB_WORLDS` crowding by opening more worlds, or lower PB's `NET.overflowAt` and rebuild the bundle.
